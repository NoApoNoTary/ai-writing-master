## 1. Objective

在不重建现有写作、审校、Rewrite 和 Handoff Runtime 的前提下，实现并验收 Personal Context Foundation：

## 5. Non-negotiable Invariants

1. **Prompt 判断，Runtime 确定。** Agent 做归纳和相关性判断；Runtime 做 schema、ID、revision、hash、路径、锁、原子写入、检索、状态、approval 和 Snapshot。
2. **任务 Snapshot 不可变。** 任务开始后只读取 Snapshot 和任务内副本；全局变化只影响后续任务。
3. **空状态唯一。** 未配置 Profile/Style 使用 `status: empty`、`revision: 0` 和 canonical empty hash，不用缺失文件或 `null` 表达。
4. **身份内去重。** Knowledge 去重键为 `(kind, normalized_content_hash, source_kind)`；跨身份同文本不合并。
5. **隐私准入确定。** `publishable` 可选；`ask_before_use` 需要任务级 approval；`private` 不进入写作 Snapshot。
6. **来源身份不混淆。** 用户经历、用户观点、外部参考和编辑推断保持不同身份。
7. **失败不静默推进。** schema、revision、hash、路径、approval 或引用失败时保留上一有效状态并非零退出。
8. **Host 合同可证明。** Deep 验证 Host 输入构造和 Manifest/hash，不扩大为 OS 级文件访问隔离声明。
9. **兼容现有能力。** `quality`、`similarity`、`handoff`、`home` 和 quick/standard/deep 语义不变。
10. **零新运行依赖。** Python 3.11+ 标准库；继续使用 `unittest`。
11. **只用合成验收数据。** 不把本机私密文章或用户资料加入 fixture/仓库。
12. **不把合成任务写成效果证明。** 它只证明工程链路真实执行。

## 7. Execution Loop

### 7.1 启动

1. **在 Terra 模型会话中启动本 Goal。** Sol 当前阶段已经完成方案、范围和验收设计；Goal mode 本身不会自动切换模型。
2. 创建 Goal，objective 使用第 1 节原文或等价完整描述。
3. 不设置 token budget，除非用户显式指定。
4. 记录 branch、HEAD、当前 `git status` 和受保护 HTML 证据。
5. 运行全量测试基线，更新验收记录。
6. 从执行清单最早未完成且依赖满足的 Goal A task 开始。

### 7.2 每轮

1. 保持至多一个 Goal A task 为当前任务。
2. 用 CodeGraph 定位符号、调用链和测试影响面。
3. 先建立或更新聚焦测试，再最小范围实现。
4. 运行聚焦测试；失败时记录事实、失败证据和下一假设。
5. 任务完成后更新 checkbox 与验收证据，再进入下一 task。
6. 每个 WP 结束运行聚焦测试和 `git diff --check`。
7. T31/T32 必须执行行为级验证，不用字符串测试代替。

### 7.3 恢复

1. 重读本合同、执行清单和验收记录。
2. 读取 `git status`、最近差异与最近验证证据。
3. 抽查已勾选任务的产物，不只相信 checkbox。
4. 从最早未完成且依赖满足的 Goal A task 继续。
5. 输入或合同变化时只失效受影响下游 task。

### 7.4 模型与审查

- Terra 负责已明确范围的编码、测试和文档执行。
- 发现架构变化、合同冲突、未知根因或范围扩大时，输出 `MODEL_SWITCH_REQUIRED: SOL`。
- T33 使用 fresh Sol reviewer subagent，输入只包含 Goal 合同、计划、代码差异、测试结果和验收记录。
- Reviewer 写入固定报告路径。子代理不可用时，保持 Goal active，转由新的 Sol review 会话完成；主体作者不自证。

## 10. Stop And Escalation

以下情况输出 `MODEL_SWITCH_REQUIRED: SOL`，记录事实和待决策问题：

- 需要增加运行依赖、数据库、向量库、后台进程或新存储服务。
- 必须修改核心 schema、放弃不可变 Snapshot 或引入自动永久学习。
- 必须改变 quick/standard/deep 的语义或重写 Handoff Runtime。
- 开始实现 Goal B/C、通用 Task Runtime、CI、自动发布或新平台。
- 同一高层测试连续修复仍不能解决根因。
- 实际修改范围明显越过 T00–T33。

同一阻断条件连续出现在至少三个 Goal turn，且没有可执行本地进展时，才调用 `update_goal(status=blocked)`。继续执行时保持 Goal 原状态，不调用不存在的 `active` 更新。
