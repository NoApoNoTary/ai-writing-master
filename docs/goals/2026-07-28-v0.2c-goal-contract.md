## 7. Draft Validation

### Top level

- 字段严格为 `schema_version/candidates`。
- `schema_version == 1` 且为真实整数。
- candidates 数量 `3..10`；数组顺序就是推荐顺序。
- candidate 字段集合严格相等。
- `candidate_id` 非空、安全、全 Brief 唯一。
- `topic/audience/angle/rationale` 为非空字符串。

### Scores

固定四维：

```text
heat | user_value | differentiation | author_fit
```

- 分数是有限的真实 `int | float`，排除 bool，范围 `0..10`。
- 每项有非空 rationale。
- `heat.score == scores.heat.value`。

### Time

- `heat.as_of`、`observed_at` 是带时区 RFC3339。
- `heat.as_of <= Runtime created_at`。
- `observed_at <= heat.as_of`。
- `source_date` 是 `YYYY-MM-DD`，不晚于 `heat.as_of` 的 UTC 日期。
- validator 接受可注入 `now`，测试不得依赖墙钟竞态。

### Evidence

- `source_url` 是可解析的绝对 `http` 或 `https` URL。
- `source_title/publisher/evidence_text` 非空。
- `content_sha256 = normalized_content_sha256(evidence_text)`。
- 稳定 ID：

```text
evidence_id = "evidence-" + canonical_sha256({
  "source_url": source_url,
  "source_date": source_date,
  "content_sha256": content_sha256
})[:16]
```

- 同一 candidate 内 Evidence ID 唯一。
- `heat.evidence_ids` 非空、无重复，且全部指向该 candidate 的 Evidence。
- Runtime 不联网验证来源内容，也不证明远端事实真实。

### Author Fit

每个 candidate 至少一个引用。

Profile 引用必须逐项等于 Snapshot 的：

```text
profile_id + revision + content_sha256
```

Material 引用的 `item_id` 必须出现在 Snapshot `materials[]`。

canonical empty Profile 的 revision 0/hash 允许被引用；评分理由必须由 Agent 自己解释信息限制，Runtime 不做语义裁决。

## 8. Canonical Research Brief

Runtime 添加受管字段并写入 `{run_dir}/research-brief.json`：

```json
{
  "schema_version": 1,
  "task_id": "TASK-C-001",
  "created_at": "2026-07-28T00:00:00+00:00",
  "inputs": {
    "brief": {"path": "brief.md", "sha256": "64-lowercase-hex"},
    "personal_context": {
      "path": "personal-context-snapshot.json",
      "snapshot_sha256": "64-lowercase-hex"
    }
  },
  "candidates": [],
  "research_brief_sha256": "64-lowercase-hex"
}
```

```text
research_brief_sha256 = canonical_sha256(document excluding research_brief_sha256)
```

持久化规则：

- 从 `status.json` 读取 `task_id`；不分配 ID，不修改 `status.json`。
- `status.json.task_id == snapshot.task_id == canonical task_id`。
- `brief.md.sha256` 使用原始 bytes。
- run-local `.research-brief.lock` 串行化竞争保存。
- canonical JSON 原子写入。
- 相同 draft、Brief hash 和 Snapshot hash 重复保存返回已有文档。
- 已存在不同文档返回 `duplicate`，保留已有文件。
- v0.2 不增加 revision/history；刷新研究使用新任务。
- verify 重算 Brief、Snapshot、Evidence 和 canonical hash；输入变化返回 `hash_mismatch`。

## 11. Research / Topic Contract

### Topic Research

触发：

- 用户明确只要选题。
- 内容契约仍是宽主题，存在多个实质方向。
- 用户要求近期热点或值得关注的话题。

输入仅限：

```text
brief.md
personal-context-snapshot.json
Manifest 明确列出的 context-materials/ITEM_ID.md

```

Deep 模式复用现有 Researcher，不新增 Agent role：

```text

to_role: researcher
expected output: research-brief-draft.json
```

### Article Research

用户/Lead 选择 candidate 后，现有文章事实研究继续生成：

```text
sources.yaml
claims.yaml
asset-manifest.yaml
research-summary.md
```

Research Brief Evidence 只支持候选排序和选题理由，不自动升级为 `claims.yaml` 中的 accepted claim。

`researcher.md` 增加两个 Manifest 模式：

```text
topic_research -> research-brief-draft.json
research       -> sources.yaml/claims.yaml/asset-manifest.yaml/research-summary.md
```

Researcher 可提出多个 Angle，但不选择最终方向。

### Missing live retrieval

缺少实时检索能力时，Agent 返回：

```json
{
  "status": "blocked",
  "code": "realtime_research_unavailable",
  "missing_capability": "web_search"
}
```

此路径不产生 draft，不创建或覆盖 `research-brief.json`。Runtime 不推断 Host 能力。
