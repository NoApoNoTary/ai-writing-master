## 6. Candidate Input Contract

`learn propose CANDIDATE.json` 接受调用方内容，不接受调用方提供 ID、状态、revision 或时间：

```json
{
  "source": {
    "task_id": "TASK-N",
    "baseline": {"path": "draft-v1.md", "sha256": "64-lowercase-hex"},
    "edited": {"path": "final.md", "sha256": "64-lowercase-hex"}
  },
  "evidence": [
    {"kind": "snippet", "before": "修改前片段", "after": "修改后片段"},
    {"kind": "diff_ref", "path": "revision-report.yaml", "ref": "changes[0]"}
  ],
  "rule": {
    "dimension": "expression",
    "guidance": "减少抽象铺垫，先给出可执行判断。",
    "scope": {"kind": "global", "value": ""}
  },
  "proposal": {
    "model": "MODEL",
    "prompt": "用于从编辑差异提取单条候选规则的完整提示词"
  }
}
```

枚举：

```text
dimension = expression | sentence | structure | stance | platform
scope.kind = global | platform | content_type | topic
```

校验：

- 所有对象字段集合严格相等。
- `baseline.path`、`edited.path` 通过 `safe_relative_path()`；两个 SHA-256 为小写 64 hex 且不同。
- `evidence` 至少一项；每项只能是 `snippet` 或 `diff_ref` 的精确 schema。
- snippet 的 `before/after` 非空且不同；diff_ref 的安全相对 `path` 和 `ref` 非空。
- `task_id`、`guidance`、`model`、`prompt` 非空。
- global scope 的 `value == ""`；其他 scope 的 value 非空。
- 人类文本在持久化前 NFC 归一化。
- Runtime 不重新认证源文件，也不判断 guidance 的语义质量。

## 7. Style Observation Contract

存储：

```text
${WRITING_MASTER_HOME}/personal-context/style-observations/OBSERVATION_ID.json
```

目录按需创建，不增加 observation index。

### Proposed

```json
{
  "schema_version": 1,
  "observation_id": "observation-0123456789abcdef",
  "revision": 1,
  "status": "proposed",
  "proposed_at": "RFC3339",
  "source": {},
  "evidence": [],
  "rule": {},
  "proposal": {},
  "content_sha256": "64-lowercase-hex",
  "observation_sha256": "64-lowercase-hex"
}
```

### Accepted / rejected

终态增加：

```json
{
  "revision": 2,
  "status": "accepted",
  "decided_at": "RFC3339",
  "decision_provenance": {"kind": "user_confirmed"}
}
```

派生规则：

```text
content = {source, evidence, rule, proposal}
content_sha256 = canonical_sha256(content)
observation_id = "observation-" + content_sha256[:16]
observation_sha256 = canonical_sha256(document excluding observation_sha256)
```

状态机：

```text
proposed -> accepted
proposed -> rejected
```

- 重复相同决定返回现有结果。
- 相反决定返回 `revision_conflict`。
- 终态不撤销；修正通过新 observation 表达。

## 8. Ready Style Profile Contract

无 accepted observation 时必须保持 Goal A 原 canonical empty Style。

有 accepted observation 时：

```json
{
  "schema_version": 1,
  "status": "ready",
  "profile_id": "style-default",
  "revision": 1,
  "updated_at": "RFC3339",
  "rules": [
    {
      "rule_id": "style-rule-0123456789abcdef",
      "dimension": "expression",
      "guidance": "减少抽象铺垫，先给出可执行判断。",
      "scope": {"kind": "global", "value": ""},
      "observation_refs": [
        {
          "observation_id": "observation-0123456789abcdef",
          "revision": 2,
          "observation_sha256": "64-lowercase-hex"
        }
      ]
    }
  ],
  "provenance": {"kind": "accepted_observations"},
  "content_sha256": "64-lowercase-hex"
}
```

确定性规则：

- 一条 accepted observation 生成一条 rule；Runtime 不做语义合并或冲突消解。
- `rule_id = "style-rule-" + observation_id` 的 16 位 hash 后缀。
- `rules` 按 `rule_id` 排序。
- `revision == accepted observation 数量`。
- `updated_at == accepted observations 最大 decided_at`。
- `content_sha256 = canonical_sha256({"rules": rules, "provenance": provenance})`。
- proposed/rejected 不进入 rules 或 provenance，也不改变 Style revision/hash。

## 10. Atomicity And Reconcile

所有 propose、decide、list 和 Style reconcile 使用现有 Context root flock 和 FD 安全原语；不要在 `ContextStore.locked()` 内再次调用会自行取锁的公开 Store 方法。

Accept 顺序：

1. 锁 Context root。
2. 读取并验证 observation。
3. 原子写 revision 2 accepted observation。
4. 从全部 accepted observations 确定性重建 Style。
5. 原子写 `style-profile.json`。

若进程在 3/4 之间终止，下一次 `initialize/read_style/decide/create_snapshot` 必须完成 reconcile。

- 当前 Style 合法但落后：重建。
- 当前 Style JSON/schema/hash 已损坏：抛出原错误，不以派生结果掩盖损坏。
- 任一 observation 损坏：reconcile 失败且保留最后有效 Style。
