## 3. Missing-retrieval compatibility decision

The three-field missing-capability response is intentionally handled **before a `topic_research` Handoff is created**:

```json
{
  "status": "blocked",
  "code": "realtime_research_unavailable",
  "missing_capability": "web_search"
}
```

This object is a Host/Lead capability response, not a Handoff Result. The existing Handoff Result schema requires Handoff identity, attempt, `agent_ref`, status-specific output/failure fields, summary and completion time. Writing the three-field object to a Manifest `result_path` would therefore be rejected by the existing Result validator or would require a change to protected `handoff.py`.

The reviewed flow is:

1. Host checks live retrieval capability.
2. If missing, Lead records the three-field response before `handoff.prepare`.
3. No Handoff, Result, `research-brief-draft.json` or `research-brief.json` is created or overwritten.
4. If available, Lead prepares the ordinary `topic_research -> researcher` Handoff and the Researcher returns a schema-valid completed Result containing the draft output.

This preserves the frozen contract's required externally visible failure semantics while remaining compatible with the existing Handoff Result schema and protected ownership boundary. `test_missing_live_retrieval_is_blocked_without_a_brief` locks the placement and no-artifact behavior.

## 4. Runtime review

### Snapshot-only dependency boundary

The module consumes `status.json`, raw `brief.md` bytes and `personal-context-snapshot.json` from the anchored run directory. It calls the shared Snapshot validator and reads only the frozen Profile tuple and selected Material IDs. A regression test replaces all global Profile, Style and Material readers with exceptions and still completes save successfully.

### Validation and error stability

The validator enforces exact fields, 3–10 unique safe candidate IDs, four finite `0..10` scores, Heat equality, timezone-aware ordering, absolute HTTP(S) URLs, normalized Evidence content hashes, deterministic Evidence IDs and Snapshot-bound author-fit references. The direct CLI maps `ContextError` to machine-readable stdout in JSON mode and `research:`-prefixed stderr in text mode.

### Persistence and path safety

The Runtime opens the run path component-by-component with directory descriptors and no-follow semantics, then uses descriptor-relative reads and writes. The lock inode is rechecked before publication. Canonical JSON is published write-once without replacing an existing destination, so concurrent different saves produce one verified winner and one `duplicate`. Tests cover ancestor retargeting, resolve/open races, symlinks, FIFOs, lock replacement and atomic-publish failure.

### Hash domains

The implementation and acceptance record distinguish:

- raw serialized file SHA-256;
- Snapshot `snapshot_sha256` over canonical document content;
- Handoff canonical Manifest hash stored in state/status;
- canonical Research Brief `research_brief_sha256` excluding its self-hash field.

The real acceptance audit recomputed each domain and found zero mismatches.
