## 6. Failure-path evidence

The final focused suite exercises the stable error protocol rather than only the happy path:

| Failure class | Evidence |
|---|---|
| malformed JSON / non-object draft | CLI returns `invalid_json` in JSON mode |
| invalid candidate count, fields, scores, time or URL | `invalid_input` |
| unpaired-surrogate Evidence text or UTC conversion overflow | normalized to `invalid_input`; no traceback |
| wrong Evidence text hash, stable Evidence ID, Profile tuple, input or self-hash | `hash_mismatch` |
| unknown Heat Evidence or Snapshot Material reference | `unknown_id` |
| missing run, draft or managed input | `not_initialized` |
| unsupported canonical schema | `schema_unsupported` |
| different second write to the same task | `duplicate`; the first canonical file remains the winner |
| run/draft symlink, FIFO, replaced lock or unsafe path | `path_escape`; FIFO cases return without blocking |
| concurrent different saves, including a recreated lock inode | no-clobber publication preserves exactly one winner; the other receives `duplicate`; the stored winner verifies |
| atomic publish failure | no partial canonical file or temporary residue remains |
| changed `brief.md`, Snapshot or canonical payload | subsequent verify returns `hash_mismatch` |
| attempted global Profile/Style/Material access | patched global readers raise, while task-Snapshot save still succeeds |
| missing live retrieval | skill contract records the three-field capability response before Handoff creation; no Handoff, draft or canonical Brief is produced |
| Handoff/Runtime seam | regression performs `prepare -> mark_running -> staged draft + Result -> complete -> promoted draft -> save -> verify` and checks input/output hashes plus effective completion |
