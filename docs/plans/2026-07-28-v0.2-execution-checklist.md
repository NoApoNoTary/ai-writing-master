## 0. Program 规则

1. v0.2 分成三个顺序 Goal；当前只启动 Goal A。
2. 任务只在真实产物和验证证据存在后勾选。
3. 从最早未完成且依赖满足的任务继续；红灯不跳过。
4. Goal A 完成后，由 Sol 根据真实接口和差异激活 Goal B；Goal C 同理。
5. 每个 Goal 独立执行全量测试、行为 smoke、构建和非作者审查。
6. 不以文件存在、测试数量、checkbox、Agent 自述或 Goal 状态代替完成证据。
7. `v0.2` 是产品里程碑，不要求修改 Python 包版本为 `0.2`。
8. 新运行时代码保持 Python 3.11+ 标准库实现。
9. 不修改、删除或暂存预存未跟踪 HTML；最终用 SHA-256、size 和 index 状态复核。

## 7. 范围变更闸门

出现以下事实时停止当前 Goal 并请求 Sol 决策：

- 需要增加运行依赖、数据库、向量库、后台进程或新存储服务。
- 必须改变核心 schema、放弃不可变快照或引入自动永久学习。
- 必须改变 quick/standard/deep 的语义或重写 Handoff Runtime。
- Goal A 开始实现 Goal B/C、通用 Task Runtime 或自动发布。
- 同一高层测试连续修复仍不能解决根因。
- 实际范围明显越过当前 Goal 合同。

普通实现细节、测试补充和当前合同内的文件调整不触发重新规划。
