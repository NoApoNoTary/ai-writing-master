# AI Writing Master 用户上手指南

这是普通用户唯一的上手文档。你只需要在已经安装 AI Writing Master 的 AI 编程工具中描述写作目标；日常写作不需要学习命令行或内部实现。

尚未安装时，先按 [README 的安装步骤](../README.md#安装) 完成一次安装，然后回到本页。

## 1. 第一次写作

### 第一步：直接说要写什么

```text
写一篇面向独立开发者的公众号文章，主题是如何选择本地 AI 工具。
希望有现实案例，语气冷静，不要营销腔。
```

新建完整文章时，系统会先显示固定的三种模式选项。直接回复序号即可：

- **快速草稿**：先拿到有依据、可继续讨论的完整版本；
- **标准写作**：完成较完整的调研、规划、写作和审校，适合常规发布；
- **深度写作**：用于重要长文，强调研究、策划、写作和审计之间的独立性。

如果你已经确定模式，也可以在第一句话中直接说明：

```text
用标准写作模式，写一篇面向独立开发者的公众号文章：如何选择本地 AI 工具。
```

### 第二步：确认写作要求

系统会把已知信息整理为一份内容契约，通常包括：

- 主题与核心问题；
- 目标读者和本次唯一目标渠道（微信公众号、X 单帖或 X Thread）；
- 文章目的、篇幅和时效；
- 需要多严格的事实依据；
- 语气、表达风格和禁用倾向；
- 是否需要配图、排版或发布准备。

信息正确时回复：

```text
确认
```

需要调整时直接指出字段：

```text
修改：读者改为第一次接触本地 AI 的普通用户；篇幅控制在 1800 字；不要做配图。
```

确认前不会开始调研或写正文。

### 第三步：查看进度和结果

流程中的摘要会保持同一结构，例如：

```text
任务：本地 AI 工具选择指南
模式：标准写作
阶段：等待内容契约确认
状态：等待用户
已完成：写作要求整理
当前动作：等待确认
等待你：确认或指出修改项
下一步：确认后开始调研
最近失败：无
```

完成后优先查看正文、来源说明、审校结果和验收说明。没有明确发布指令时，只生成可审阅结果，不会公开发布。

## 2. 补充素材

### 开始时一起提供

可以在首个请求中附上网页、视频、Markdown、PDF、图片、截图、图表、历史文章或个人经历记录：

```text
用标准写作模式写一篇公众号文章。
参考资料：
- https://example.com/report
- ./materials/interview.md
- ./materials/chart.png
先核对事实和素材用途，再开始写作。
```

系统会先返回素材接收结果，区分已接收、已提取、等待处理、失败和需要你确认的项目。素材被接收不代表其中的陈述已经被当作事实采用。

### 写作途中继续补充

直接说明新增内容及用途：

```text
补充这份行业报告和一张产品截图。
报告用于核对市场数据，截图只用于说明界面，不要把宣传文案当作事实。
```

如果已完成部分会受到影响，系统会先说明处理范围。具备输入依赖校验时只重做受影响部分；缺少该能力时保留现有版本，并明确哪些阶段需要重新处理。

### 素材失败时怎么处理

- 非关键素材失败时，其余素材继续处理，并明确失败项的影响；
- 关键依据缺失、已经影响所选模式的交付标准时，任务停止并保留已有内容；
- 你可以补充替代来源后发起新的继续请求。

## 3. 修改结果

### 修改方向或要求

在正文生成前，可以直接修改内容契约：

```text
修改：不要做工具横评，改为解释选择方法；结论要给出三个明确判断标准。
```

系统会列出受影响的调研、结构或写作部分，再按新要求继续。

### 修改已经生成的正文

指出保留项、修改项和验收标准，避免只说“再润色一下”：

```text
保留现有事实、来源和核心结论。
重写开头两段，删除铺垫，第一段直接给出判断。
把第三节压缩到 300 字，并列出具体改动。
```

也可以要求局部修订：

```text
只修改“成本”一节：补上维护时间和失败成本，不改其他章节。
```

已有草稿和已验收结果不会被静默覆盖；修改应形成可对照的新版本，并说明哪些问题已经处理、哪些仍待确认。

### 对结果不满意时

优先说明问题证据，而不是只要求“更好”：

```text
问题：第二节只有观点，没有来源；结尾重复前文；语气过于肯定。
请补证据、删除重复，并把结论改成带适用条件的判断。
```

这样可以缩小返工范围；只有当前任务具备输入依赖校验时，系统才保证只重做受影响部分。

## 4. 改写已有文章

```text
把 ./article.md 改写成 X Thread。
保留事实和立场，但重构开头、信息顺序和每条帖子的推进关系。
```

改写已有文章不触发新文章的三种模式选择。若未指定目标渠道，系统会让你从微信公众号、X 单帖和 X Thread 中选择一个；一次只生成一个渠道成品。

之后说“再生成一个 X 单帖”会创建新的改写任务，复用同一份源稿和已核对的事实分析，不把前一个渠道版本作为输入。一个版本失败不会修改源稿或已经完成的版本。微信公众号成品还包含格式化 Markdown、HTML 和封面。

## 5. 只做一个环节

以下请求会直接执行对应工作，不启动完整写作流程：

```text
只给我三个选题方向，不写正文。
```

```text
只审校这篇文章，分别列出事实问题、结构问题和表达问题。
```

```text
只修改标题，正文保持不变。
```

## 6. 任务停止时会看到什么

所选模式在开始前未就绪时，任务会在调研和写作前停止：

```text
所选的{模式显示名}当前未就绪，任务已停止，尚未进入调研或写作。

如需反馈，请提交 Issue，并附上：
诊断编号：WM-CAP-001
版本：VERSION
```

系统会把 `{模式显示名}` 替换为本次选择的“快速草稿”“标准写作”或“深度写作”。

运行途中出现影响交付标准的问题时，会保留已有内容并停止：

```text
任务在事实核查阶段停止，未切换到其他写作模式。
已有内容已保留。如需反馈，请提交 Issue 并附诊断编号：WM-RUN-001。
```

系统只提醒你提交 Issue，不会自动提交，也不会替你生成 Issue 草稿。

## 7. 你会收到什么

完整写作通常包含：

- 最终正文；
- 来源与关键事实说明；
- 素材清单；
- 审校与修订记录；
- 验收说明；
- 当前渠道要求的完整成品；微信公众号包含格式化 Markdown、HTML 和封面，X 单帖或 X Thread 包含逐项通过渠道审查的正文；
- 你另外明确要求的配图或其他产物。

当前渠道未要求、且你未另外请求的视觉或排版不属于缺失项。公开发布始终是交付后的独立动作。
