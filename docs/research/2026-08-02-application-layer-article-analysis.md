## 五篇文章逐篇拆解

### A1：新闻触发型配置教程

- **类型**：产品新闻 + 工具接入教程。新闻只负责建立“为什么现在做”，主体负责“怎么做成”。
- **开头**：先用价格、榜单和速度建立性价比，再承诺“两种方法、最快一行命令”。读者在进入步骤前已经知道收益和完成成本。
- **结构**：准备 Codex/API Key → CLI 一键脚本（区分 Mac/Linux 与 Windows）→ GUI 路线 CC Switch → 限制、备份和恢复。
- **操作闭环**：给出可复制命令、配置目录和文件名；用 `/model` 中出现目标模型定义“成功”；用备份目录和再次运行脚本定义“回滚”。
- **证据与量化**：输入/输出 token 单价、与竞品分差、脚本自动完成的四项工作、不到一分钟、三种 Codex 形态共用配置。
- **交付物 / 行动**：读者最终得到一个可用的 DeepSeek-Codex 配置，并能验证、恢复。CTA 是创建 Key 后在 CLI 或 GUI 两条路线中任选其一。
- **局限**：价格和榜单是作者引用而非正文内可审计证据；安全性主要依赖“官方脚本”背书，未带脚本审阅或最小权限说明。

**独特价值**：五篇中“可复现性”和“故障恢复”最完整。它不是步骤多，而是有明确的前置条件、分流、验收和回滚。[原文](https://mp.weixin.qq.com/s/NF89SBEXV48Fj0GWIrK8Zg)

### A2：同条件实测型决策文章

- **类型**：新品首测 + 替代方案比较，核心任务是帮助读者做模型/平台选择，而不是完整教学。
- **开头**：用同一虚构品牌在两款模型中的拼写差异切入，并把错误直接换算成商业后果：“品牌名错，成片作废”。随后前置给出总体结论。
- **结构**：耳机广告 A/B 测试 → 分辨率、文字、脚本遵循度和价格比较 → 能量饮料“一抽四” → 真人末日短剧与单镜头返工 → 总结交付质量和成本。
- **操作步骤**：同平台、同提示词、同 Skill，只替换模型；另有上传参考图、选择生成数量、重做单一分镜等操作。它提供的是“测试协议”，不是按钮级教程。
- **证据与量化**：3 类任务、2K 对 720p、像素量差异、4 个并行方案、15 秒分镜、每秒价格和单支广告/单集短剧的估算成本；同时展示成功和发型偏差等失败样本。
- **交付物 / 行动**：交付的是可供决策的视频样本、多个创意方向和局部返工结果；CTA 是带着自己的素材在 LibTV 复测。
- **局限**：完整提示词、源素材和原始输出没有作为可下载测试包提供，外部读者难以严格复验；“画质八成”等仍属主观判断。

**独特价值**：以真实失败点和同条件对照，把“新模型更强”改造成可观察的采购/生产决策。[原文](https://mp.weixin.qq.com/s/3tFmTXqIq9stcRkk8OZVGw)

### A3：概念解释 + 迁移清单

- **类型**：行业概念/协议更新分析，后半段嵌入开发者迁移指南，是最接近“理念文章增加应用模块”的样本。
- **开头**：用月下载量增长制造重要性，再用 GitHub、Notion、数据库三个熟悉任务解释 MCP 的实际存在，之后才提出“有状态”这个底层问题。
- **结构**：USB-C 类比解释 MCP → 生态时间线 → 有状态部署痛点 → 无状态、MRTR、HTTP 头、缓存等变化 → 破坏性影响和取舍 → HTTP 请求示例 → 6 步迁移 → 新手安装建议。
- **操作步骤**：删除握手、增加发现接口、移除 session 依赖、增加缓存提示、迁移 Tasks API、升级 SDK；并给出新版 HTTP 请求的字段形态。
- **证据与量化**：下载量、采用率、公开服务器数、生态时间线、12 个月过渡期、官方 SDK 数量、连接器数量和“先装 3 个”的明确建议。
- **交付物 / 行动**：老项目读者得到迁移检查表和请求骨架；新用户得到最小 MCP 组合。完成状态仍偏抽象，没有兼容测试、回滚命令或迁移前后样例仓库。
- **局限**：数据很多，但正文没有逐项附原始出处；迁移清单能指导评估，尚不足以单靠文章完成升级。

**独特价值**：证明“思考层”不必被替换，只需在读者理解完变化后，增加一个与角色匹配的操作出口。[原文](https://mp.weixin.qq.com/s/A9wcgYLcqpxs-857J16QdA)

### A4：零基础端到端项目教程

- **类型**：安装教程 + 项目式工作坊。目标不是“认识 Hermes”，而是完成一个会持续教学并自我改进的赛博导师。
- **开头**：一句话同时交代工具、目标成果和适用人群；概念介绍只服务于后续方案选择。
- **结构**：Hermes 定位 → 安装、模型、语言、IM → 多 Agent/多模型 → Ollama 本地模型 → 新建学习 Agent → 导入需求文档 → 需求访谈和自动搭建 → 定时任务 → 上课、批改、调整计划和迭代 Skill。
- **操作步骤**：界面路径、官网、提示语、Agent 创建选项、模型分工均有说明；关键复杂度通过一份可领取的需求文档封装。
- **证据与量化**：展示健康检查报告、本地文件夹、学习路线网站、错题本、周报、排程和课程互动。量化主要是 7×24 小时、多 Agent、多模型，成本/耗时/硬件门槛较弱。
- **交付物 / 行动**：Hermes + Ollama 环境、独立学习 Agent、长期计划、学习记录、错题本、进度网站和定时提醒。CTA 是下载需求文档并让 Hermes 初始化。
- **局限**：大量关键动作依赖截图；显存、模型选择、权限、失败恢复和安全边界没有形成可检索的文字检查表。

**独特价值**：用“可下载需求文档”把一篇长教程压缩成可执行模板，并把一次性产出升级为长期反馈循环。[原文](https://mp.weixin.qq.com/s/l4iByUtZ6o_WOSKtjhUapw)

### A5：能力阶梯 + 职业场景图谱

- **类型**：新手能力导览，依次把产品能力绑定到职业任务，而非围绕一个项目走到底。
- **开头**：先指出读者只用了“20%”，再承诺进入“前 1%”的使用水平；这是身份差距和损失厌恶驱动，不是证据驱动。
- **结构**：电脑版/新办公任务前置 → 本地文件操作 → 浏览器采购 → Skill 的作用、内置 Skill、安装 Skill、创建 Skill → 定时任务与能力组合。
- **操作步骤**：每个能力都配一个职业场景：汽车销售报价、PDF 转 Word 并批注、行政采购比价、轻食视频、自建夸夸机 Skill。步骤偏演示，完整提示词多在截图中。
- **证据与量化**：主要证据是交付结果——PDF、交互网页、Word 批注、比价表、购物车、视频和 Skill。标题中的 20%/99% 属修辞性数字，文章没有测量方法。
- **交付物 / 行动**：让读者快速找到与自己岗位相邻的第一个用例；结尾明确要求只选一两个能力真正使用。
- **局限**：覆盖广但每条路径浅，缺少完成标准、错误处理、成本和复现实验材料。

**独特价值**：适合陌生产品的第一篇“应用地图”，用角色任务降低理解成本；不适合作为深度教程的替代品。[原文](https://mp.weixin.qq.com/s/j0kIG3EEmgcupO37MQBJNg)

## 横向比较

| 文章 | 最适合解决的问题 | 可复现性 | 结果可观察性 | 证据可审计性 | 客观量化 | 验收/回滚 |
|---|---|---|---|---|---|---|
| A1 配置教程 | “我现在怎样接入？” | 高 | 高 | 中 | 高 | 高 |
| A2 对比实测 | “两个方案选哪个？” | 中 | 高 | 中 | 高 | 中 |
| A3 解释+迁移 | “变化意味着什么、我要改什么？” | 中 | 中 | 中 | 高 | 低 |
| A4 项目教程 | “怎样从零做出一个完整系统？” | 中 | 高 | 中低 | 中 | 低 |
| A5 能力地图 | “这个产品能替我做哪些事？” | 中低 | 高 | 低 | 低 | 低 |

这里最重要的区分是：**“有案例”不等于“可操作”，“有步骤”也不等于“可交付”。** 应用层文章至少要闭合：输入 → 动作 → 产物 → 验收；操作层再增加异常、修复和回滚。A1 完整闭环，A2 强在决策证据，A4 强在最终系统，A5 强在场景覆盖，各自不是同一种“教程”。

两位作者也形成明显差异：

- **AI信息Gap**：数据/冲突开头，正文密度高，图片少；擅长把新闻变成选择、配置或迁移决策。
- **秋芝2046**：口语化承诺，截图密集，以角色场景和结果展示推动新手；擅长把陌生工具变成“我能做什么”。

## 可复用但不抄袭的结构模式

### 1. 先选择“价值机制”，再选择文章形式

不要建立一个笼统的“应用文”类型。建议最少保留以下路由：

1. **配置/操作教程**：流程稳定、可在一次会话内完成；参考 A1。
2. **对比实测**：读者面对两个以上方案，核心价值是选择；参考 A2。
3. **解释 + 行动清单**：主题天然偏概念，但变化会影响特定角色；参考 A3。
4. **端到端项目**：多个步骤最终组成一个持续使用的系统或作品；参考 A4。
5. **能力/场景地图**：产品很新、受众很广，先帮助读者找到第一个用例；参考 A5。
6. **纯分析/观点**：不存在可信、稳定、可复现的行动时保留；不要为了“应用感”硬编步骤。

### 2. 通用的“应用闭环”骨架

任何应用型路由都应回答七个问题：

1. **谁在什么情境下遇到什么任务？**
2. **做之前需要什么账号、素材、权限、软件或知识？**
3. **最短路径是什么？是否需要按系统/熟练度分流？**
4. **会产出什么文件、页面、配置、视频或决策？**
5. **怎样一眼判断成功？**
6. **最常见的限制、失败和回滚方式是什么？**
7. **下一步是复制命令、下载模板、带素材复测，还是只选一个场景开始？**

这七项比“多写几个步骤”更关键。缺少第 4、5 项时只是操作描述；缺少第 6 项时还不是可靠教程。

### 3. 概念文章的最小“应用模块”

不必把所有理念文章重写成保姆级教程。像 A3 一样，在分析后追加一个短模块即可：

- **这件事影响谁 / 不影响谁**；
- **10 分钟内能做的下一步**；
- **一份可复制清单、命令、模板或请求骨架**；
- **预期输出与检查方式**；
- **暂时不要做什么**。

这会保留原有思考优势，同时把认知转成行为。

### 4. 量化必须服务于决策

可优先采集：时间、直接成本、步骤数、输出数量、准确率、分辨率、失败次数、返工范围、产物数量、前后差异。避免把“99%”“只用了 20%”“画质八成”这类无测量方法的数字当成可量化价值。它们可以是标题修辞，不能替代验收数据。

### 5. 用交付物而不是“学会了”定义完成

五篇的有效交付物包括：可工作的模型配置、四条视频方案、迁移清单与请求样例、学习进度网站、报价 PDF/网页和 Skill。`ai-writing-master` 可在生成前要求作者填一句：

> 读者执行完本文后，手里会多出 ______；他通过 ______ 判断已经完成。

填不出来时，优先走分析/认知路由，而不是伪装成教程。

## 对路由层的直接建议

AI 推荐文章类型时，只需按以下顺序判断：

1. 有明确的二选一/多选一决策，且能做同条件测试 → **对比实测**。
2. 有单一、稳定、可复现的完成路径 → **配置/操作教程**。
3. 有明确最终作品，需串联多个工具和反馈循环 → **端到端项目**。
4. 是新产品且受众尚不知道适用场景 → **能力/场景地图**。
5. 是概念、政策、协议或趋势变化，能影响某类人的工作 → **解释 + 行动清单**。
6. 没有可信行动，或行动高度依赖未知条件 → **纯分析/观点**。

用户可以手选；AI 推荐时同时说明一句理由，并标出是否需要“应用模块”。不要把路由做成僵硬文体模板：它的职责只是选择价值闭环，具体声音和叙事仍由现有写作流程决定。

## 核心结论

用户的方向判断基本成立，但真正需要补的不是统一的“操作感”，而是**从选题到价值闭环的路由**。这五篇覆盖了五种不同价值：接入、选择、迁移、建成系统、发现用例。最值得吸收的是三点：

1. 开头尽快说明现实任务、收益和完成成本；
2. 正文围绕可观察产物组织，而不是围绕功能或概念目录组织；
3. 结尾给出验收、限制和一个明确动作。

如果只增加截图、案例和步骤，文章会更像教程但价值仍不可测；如果补齐“交付物 + 验收 + 异常/回滚”，应用层才真正成立。
