# 三遍审校机制 (Three-Pass Review)

## 🎯 目标

**将AI味从60%降到<30%**

- 第一遍：确保内容正确
- 第二遍：去除AI味，增加人味
- 第三遍：打磨细节

---

## 📋 总体原则

### 每遍审校的产出
- 第一遍 → `draft-v2.md`
- 第二遍 → `draft-v3.md`
- 第三遍 → `final.md`

### 每遍都要
- ✅ 创建新版本文件（不覆盖上一版）
- ✅ 记录修改清单
- ✅ Think Aloud 说明修改理由

---

## 🔍 第一遍：内容审校（逻辑、事实、结构）

### 目标
确保文章**准确、合理、完整**

### 检查清单

#### 1. 事实准确性 ✅

**检查项**：
- [ ] 数据正确（没有编造）
- [ ] 时间准确
- [ ] 产品名称、版本号正确
- [ ] 引用来源真实可查
- [ ] 技术细节无误

**示例问题**：
```markdown
❌ 问题："Claude Sonnet 4.5 拥有100万token上下文"
✅ 修正："Claude Opus 4.8 拥有200k token上下文"
         （模型名称错误 + token数错误）

❌ 问题："这个功能在2025年1月发布"
✅ 修正：删除或改为"约在2025年Q1发布"（不确定就不写具体日期）
```

#### 2. 逻辑清晰度 🧠

**检查项**：
- [ ] 前后无矛盾
- [ ] 推理合理
- [ ] 因果关系正确
- [ ] 无跳跃性结论

**示例问题**：
```markdown
❌ 问题：
段落1: "AI工具让我效率翻倍"
段落3: "用AI后反而更慢了"
→ 前后矛盾

✅ 修正：
段落1: "AI工具在某些场景让我效率翻倍"
段落3: "但在需要深度思考的场景，用AI反而更慢"
→ 明确边界，无矛盾
```

#### 3. 结构合理性 📐

**检查项**：
- [ ] 无跑题
- [ ] 层次分明
- [ ] 过渡自然
- [ ] 开头与结尾呼应

**结构问题**：
```markdown
❌ 问题：
第1部分：介绍工具
第2部分：突然讲自己的故事
第3部分：又回到工具功能
→ 结构混乱

✅ 修正：
第1部分：个人故事引入
第2部分：介绍工具（自然过渡）
第3部分：使用技巧
第4部分：总结感悟（呼应开头）
→ 结构清晰
```

#### 4. 无编造内容 🚫

**重点检查**：
- [ ] 所有数据都有来源
- [ ] 案例都是真实的
- [ ] 不确定的信息已标注"约"、"估计"
- [ ] 个人经历是用户真实提供的

**编造识别**：
```markdown
❌ 编造：
"根据我在Google的工作经验..."
→ 用户从未说过在Google工作

❌ 编造：
"测试显示性能提升了47%"
→ 没有进行过测试

✅ 正确：
"从我的使用感受看，速度明显更快了"
→ 主观感受，不是伪造数据
```

#### 5. 段落迷你论点检查 ⭐

**操作方法**：
在每段旁边标注该段的核心论点（一句话）

**示例**：
```markdown
[论点：周五发现Bug很难解决]
周五下午4点，我盯着一个Bug盯了2小时。各种方法都试过了，
日志也看了，就是找不到问题。人都麻了。

[论点：Claude Code 10分钟解决]
突然想起Claude Code，让它帮我分析。10分钟，准确定位到问题：
一个异步回调的时序问题。

[论点：震惊于效率提升]
那一刻我愣住了。2小时 vs 10分钟，差距太大了。
```

**串联测试**：
```
论点1：周五发现Bug很难解决
论点2：Claude Code 10分钟解决
论点3：震惊于效率提升
→ 逻辑链条清晰 ✅
```

**不通过示例**：
```markdown
[论点：？？？]
AI技术发展很快。工具也越来越多。我们要学会使用。
市面上有很多选择。每个工具都有特点。
→ 没有明确论点，需要重写 ❌
```

---

### 输出

**修改清单**：
```markdown
## 第一遍审校修改清单

### 事实修正
- 第12行：Claude Sonnet 4.5 → Claude Opus 4.8
- 第45行：删除无法核实的"85%用户"数据

### 逻辑修正
- 第3段：补充"在某些场景"限定，避免与第5段矛盾
- 第7段：删除跳跃性结论，补充推理过程

### 结构调整
- 将原第4段移至第2段（更自然的过渡）
- 第6段拆分为两段（论点太多）

### 段落论点
第1段：个人遇到问题的具体场景
第2段：尝试解决但失败
第3段：使用AI工具快速解决
第4段：对比效率提升的震撼
→ 逻辑链条完整 ✅
```

**保存**：
```bash
cp draft-v1.md draft-v2.md
# 应用所有修改
```

## 🎨 第二遍：风格审校（降AI味）⭐⭐⭐

### 目标
**去掉AI味，增加人味**

### AI味特征清单

#### 1. 删除套话 ❌

**常见套话**：
```markdown
❌ "在当今时代"
❌ "在这个...的时代"
❌ "综上所述"
❌ "总而言之"
❌ "值得注意的是"
❌ "需要强调的是"
❌ "归根结底"
❌ "不可忽视"
❌ "显而易见"
❌ "毫无疑问"
```

**修改示例**：
```markdown
❌ AI味：
在当今AI技术飞速发展的时代，编程工具也在不断进化。
综上所述，Claude Code是一个值得尝试的工具。

✅ 人味：
Claude Code出了。我用了两周，确实比Cursor好用。
（直接切入，删除所有套话）
```

#### 2. 拆解AI句式 ❌

**AI特征句式**：
```markdown
❌ "不仅...而且..."
❌ "既...又..."
❌ "一方面...另一方面..."
❌ "不是...而是..."
❌ "从...到..."
```

**修改示例**：
```markdown
❌ AI味：
Claude Code不仅提高了开发效率，而且还降低了出错率。
既节省了时间，又提升了代码质量。

✅ 人味：
Claude Code让我写代码快了很多。出Bug也少了。
一天能省3-5小时，这是真的。
（拆成短句，删除工整句式）
```

#### 3. 替换书面词汇 ❌→✅

**常见书面词汇替换表**：

| 书面词汇 | 口语化替换 |
|---------|-----------|
| ❌ 显著提升 | ✅ 快了很多 / 提升了X% |
| ❌ 充分利用 | ✅ 用好 / 把...用起来 |
| ❌ 进行操作 | ✅ 直接用动词（"点击"、"运行"）|
| ❌ 相关工作 | ✅ 具体说做什么 |
| ❌ 某种程度上 | ✅ 算是 / 多少有点 |
| ❌ 有效缓解 | ✅ 好多了 / 解决了大部分 |
| ❌ 进而更好地 | ✅ 更好地（删除"进而"）|
| ❌ 通过XX方式 | ✅ 直接说怎么做 |

**修改示例**：
```markdown
❌ AI味：
通过充分利用Claude Code的能力，可以显著提升开发效率，
进而更好地完成相关工作。

✅ 人味：
用好Claude Code，你的开发速度能快不少。
我测下来，平均每个项目省3-5小时。
```

#### 4. 口语化改写 🗣️

**口语化技巧**：

**技巧1: 像说话一样写**
```markdown
❌ 书面："该工具具有三个显著特点"
✅ 口语："这个工具有3个特别厉害的地方"

❌ 书面："笔者认为此方案较为合理"
✅ 口语："我觉得这个方案还不错"
```

**技巧2: 使用"你"、"我"**
```markdown
❌ 书面："用户可以通过此功能..."
✅ 口语："你可以用这个功能..."

❌ 书面："本文将介绍..."
✅ 口语："我今天要讲..."
```

**技巧3: 允许不完整句**
```markdown
❌ 完整："这个功能非常强大，值得尝试。"
✅ 不完整："这功能，强。试试。"
           （更有节奏感，更口语）
```

#### 5. 加入真实细节 📊

**空洞 → 具体**：

```markdown
❌ 空洞：
"效率提升了很多"

✅ 具体：
"以前一个下午的活，现在半小时搞定"
"上周重构项目，我以为要3天，第二天就上线了"
```

```markdown
❌ 空洞：
"很多人在用"

✅ 具体：
"我认识的5个程序员朋友，4个在用"
"公司技术群里，每天都有人讨论"
```

**数字化表达**：
- ✅ "省了3-5小时"（不是"省了很多时间"）
- ✅ "50万阅读"（不是"很多人看"）
- ✅ "10分钟定位Bug"（不是"很快解决"）

#### 6. 加入个人态度 💭

**中立 → 有立场**：

```markdown
❌ 中立：
"Claude Code可能会对开发流程产生一定影响"

✅ 有立场：
"Claude Code真的改变了我的写代码方式"
"我现在离不开它了"
```

```markdown
❌ 中立：
"该工具存在一些不足之处"

✅ 有立场：
"但有个问题很烦：经常连不上"
"这点让我很头疼"
```

**加入情绪**：
- ✅ "我愣住了"
- ✅ "真的震惊"
- ✅ "有点焦虑"
- ✅ "很兴奋"

---

### 完整对比示例

#### ❌ AI味版本（60%）

```markdown
在当今AI技术飞速发展的时代，编程工具也在不断进化。通过充分利用
Claude Code的相关功能，可以显著提升开发效率，进而更好地完成工作任务。

该工具不仅具有代码补全功能，而且还能进行代码审查。从某种程度上来说，
这有效缓解了开发人员的工作压力。综上所述，Claude Code是一个值得尝试的工具。
```

#### ✅ 人味版本（20%）

```markdown
Claude Code出了。我用了两周，确实比Cursor好用。

周五下午4点，我盯着一个Bug盯了2小时。突然想起Claude Code，10分钟就定位到问题。
那一刻我愣住了。

上周重构项目，我以为要3天，结果第二天就上线了。数字不夸张，是真的。
平均每个项目能省3-5小时。

但有个矛盾：AI越好用，我越焦虑。它写代码太快了，我开始怀疑自己的价值。
```

**对比分析**：

| 维度 | AI味版本 | 人味版本 |
|------|---------|---------|
| 开头 | 套话："在当今时代" | 直接切入："Claude Code出了" |
| 句式 | 工整："不仅...而且..." | 短句："我愣住了" |
| 词汇 | 书面："显著提升" | 口语："快了很多" |
| 细节 | 空洞："提升效率" | 具体："省3-5小时" |
| 态度 | 中立："值得尝试" | 有立场："我越焦虑" |
| 情绪 | 无 | 有："愣住了"、"焦虑" |

## ✨ 第三遍：细节打磨（标点、排版、节奏）

### 目标
**让文章读起来舒服、自然、有节奏**

### 检查清单

#### 1. 句子长度与节奏 ⭐⭐⭐

**原则**：
- ✅ 15-25字为主
- ✅ 但必须有变化
- ✅ 短句(5-10字) + 中句(15-25字) + 长句(25-35字)交替
- ❌ 避免连续3句以上同样长度

**节奏检查法**：
1. 标记每句话的字数
2. 观察分布：是否有变化？
3. 找出单调区域
4. 调整：插入短句或长句打破单调
5. 大声朗读：感受呼吸和节奏

**示例**：

❌ **单调版本**（都是中等长度）
```markdown
周五早上我发了一条推文。(11字)
中午看了一眼数据很不错。(11字)
晚上再看的时候已经爆了。(11字)
我感到非常震惊和意外。(10字)
```
→ 节奏平淡，像机器人

✅ **有节奏版本**
```markdown
周五早上，我在X上发了一条关于AI换脸的推文。(20字-中)
中午看了一眼，1万多浏览，还不错。(15字-中)
到晚上再看，50万了。(9字-短) ← 短句制造停顿
我愣了。(3字-极短) ← 极短句加强情绪
```
→ 有节奏，有呼吸感

#### 2. 段落长度 📱

**手机阅读原则**：
- ✅ 3-5行为主（手机屏）
- ✅ 重要信息可以独立成段
- ✅ 避免超过8行的段落

**段落问题**：
```markdown
❌ 过长段落（12行）：
AI工具的出现改变了很多东西。首先是效率提升，原来需要几天的工作现在几小时就能完成。
其次是质量改善，AI能发现人类容易忽略的问题。再次是成本降低，不需要雇佣那么多人了。
但同时也带来了新的挑战，比如如何保证AI生成内容的准确性，如何处理AI可能带来的安全风险，
如何平衡AI的效率和人类的创造力。这些都是需要我们认真思考的问题。

→ 读起来累，手机上要滑很久
```

✅ **拆分段落**：
```markdown
AI工具的出现改变了很多东西。

首先是效率。原来几天的活，现在几小时搞定。

其次是质量。AI能发现人类容易忽略的Bug。

但也有新挑战。准确性怎么保证？安全风险怎么防？人的创造力会不会被替代？

这些都值得思考。

→ 清晰，好读，手机上舒服
```

#### 3. 标点自然度 📝

**常见问题**：

**问题1: 过度使用顿号**
```markdown
❌ "效率高、质量好、成本低、速度快"
✅ "效率高，质量好，成本也低"
   （删除最后一个，改成自然表达）
```

**问题2: 逗号滥用**
```markdown
❌ "我觉得，这个工具，确实很好用，值得推荐"
✅ "我觉得这个工具确实很好用，值得推荐"
   （删除不必要的逗号）
```

**问题3: 感叹号过多**
```markdown
❌ "太棒了！真的很好用！强烈推荐！"
   （过度兴奋，不自然）
✅ "太棒了！真的很好用。"
   （适度使用感叹号）
```

#### 4. 排版美观度 🎨

**Markdown规范**：
- ✅ 中英文之间加空格
- ✅ 数字与单位之间加空格
- ✅ 标点使用中文标点
- ✅ 代码块正确标注语言

**示例**：
```markdown
❌ 不规范：
我用的是ClaudeCode,它支持Python和JavaScript。
文件大小10MB，用时5分钟。

✅ 规范：
我用的是 Claude Code，它支持 Python 和 JavaScript。
文件大小 10 MB，用时 5 分钟。
```

#### 5. 节奏变化 🎵

**创造音乐感**：

**技巧1: 短句制造停顿**
```markdown
我试了很多方法。都不行。最后用了Claude Code。10分钟搞定。
（短句像音乐中的休止符）
```

**技巧2: 长句积累情绪**
```markdown
那一刻，我坐在电脑前，盯着屏幕上跳动的代码，突然意识到一个问题：
AI写代码的速度已经超过了我，那我的价值到底在哪里？
（长句适合表达复杂情绪）
```

**技巧3: 问句引发思考**
```markdown
但这带来一个问题：AI越强，人的价值怎么体现？

是放弃抵抗，完全依赖AI？
还是找到AI做不到的事？
还是学会和AI协作？

我还在想。
```
