# 创意排水：角度排空与差异化

创意排水的目标不是强行制造反常识，而是在正式写作前排除模型和行业最容易给出的默认答案，留下有证据、对读者有用且足够具体的编辑角度。

## 输入

- `brief.md`
- `channel-contract.yaml`
- 已接受的 `claims.yaml`
- `research-summary.md`
- 用户明确提供的个人素材及其来源位置

调研尚未完成时，可以先列待验证角度，但不得把待验证内容写成事实结论。

## 硬约束

1. 角度必须受现有证据支持，或明确标记为待验证假设。
2. 第一人称经历、时间、地点、人物、对话、测试结果和感官细节只来自 `user_provided` material。
3. 情绪、口语和反转只是表达手段，不构成差异化证据。
4. 不为了显得独特而夸大因果、删除边界或制造冲突。
5. 对用户展示候选角度、取舍和最终选择，不展示隐藏推理过程。

## 执行流程

### Step 1：列出默认答案

围绕主题快速列出 5–10 个最容易出现的观点、结构和开头。这里只写简短命题，不扩写正文。

逐项执行四个检查：

- **换题测试**：替换主题名后仍成立，说明过于通用。
- **证据测试**：现有来源并未支持，说明只是顺口判断。
- **决策测试**：读者看完仍不知道如何判断或行动，说明价值不足。
- **重复测试**：多个候选只是标题措辞变化，合并为同一默认角度。

示例：

```text
默认角度：AI 编程工具带来效率，也带来挑战。
问题：替换成任何新技术都成立；没有说明效率发生在哪里，也没有给出选择条件。
处理：排除。
```

### Step 2：建立排除清单

把默认答案按原因归类：

```yaml
discarded_angles:
  - angle: "候选命题"
    reason: generic | unsupported | no_reader_decision | duplicate | wrong_scope
    note: "为什么排除"
```

排除清单用于防止后续大纲又回到熟悉套话，不进入正文。

### Step 3：从约束中寻找有效角度

按以下顺序生成 3–5 个候选角度：

1. **边界**：结论在哪些条件下成立，在哪些条件下失效。
2. **取舍**：获得一个收益时付出了什么成本。
3. **矛盾**：两个都有证据的事实为何同时存在。
4. **决策条件**：不同读者应依据什么标准做不同选择。
5. **证据异常**：原始资料中有哪些结果偏离常见叙述。
6. **真实素材**：用户提供的经历能支持什么有限判断。

示例：

```text
主题：AI 编程工具是否提升效率
候选角度：代码生成速度不是最终指标；审查、返工和上下文切换成本共同决定净效率。
证据要求：需要分别支持生成收益和后续校验成本，正文保留适用场景。
读者决策：帮助读者判断哪些任务适合交给工具，哪些任务应保持人工主导。
```

### Step 4：评分与选择

每个候选角度按 1–5 分评估：

| 维度 | 问题 |
|---|---|
| 证据强度 | 已接受的 claim 是否足以支撑 |
| 读者价值 | 是否改变读者的理解、判断或行动 |
| 具体程度 | 是否包含对象、条件、机制或结果 |
| 差异程度 | 是否明显区别于排除清单中的默认答案 |
| 写作可行性 | 当前素材是否足以完成，不依赖补造细节 |

优先选择证据强度和读者价值都不低于 4 分的角度。差异程度高但证据薄弱的候选保留为研究问题，不进入正式大纲。

### Step 5：形成编辑结论

将最终选择写入 `editorial-brief.md`：

```markdown
## 核心角度
- 一句话判断：
- 目标读者：
- 读者看完后应形成的判断或行动：
- 支持主张：claim-001, claim-002
- 最强反方：
- 适用边界：
- 明确排除：

## 采用理由
- 相比默认角度增加了什么：
- 当前证据为何足够：
- 仍需保留哪些不确定性：
```

## 个人素材使用规则

如果角度使用用户经历，在编辑稿中登记：

```yaml
personal_material:
  source: "本次对话、用户文件或素材 ID"
  supported_statement: "素材实际支持的最小陈述"
  allowed_use: opening | example | evidence | reflection
  boundary: "不得扩写的部分"
```

用户没有提供个人经历时，使用观察、问题、证据或判断开场，不添加“朋友说”“我测试过”“上周发生”等替代故事。

## 结束条件

- 至少排除了三个可替换主题的默认角度。
- 最终角度关联已接受的 claim 或明确的待验证任务。
- 读者决策、最强反方和适用边界已经写清。
- 个人素材均有来源位置，未出现扩写式细节。
- `editorial-brief.md` 足以让 Writer 在不读取排水过程的情况下开始写作。
